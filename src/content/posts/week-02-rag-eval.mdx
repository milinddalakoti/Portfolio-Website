## What shipped

A side by side comparison harness for **Pinecone / Weaviate / pgvector** against the Week 1 Mini-RAG Reader, plus a **FAISS baseline** that runs locally with zero API keys.

**Architecture:** every store implements the same `VectorStore` Protocol (`upsert / query / delete / stats`). New store = one new file. The eval harness + canonical Q&A set are store agnostic.

**Adapters:**
- `FaissStore` (in memory baseline)
- `PineconeStore` (serverless free tier; needs API key)
- `WeaviateStore` (14 day cloud sandbox; needs cluster URL + key)
- `PgVectorStore` (local Docker pgvector or Supabase free tier; needs conn str)
- 4 stores scaffolded (FAISS, Pinecone, Weaviate, pgvector). FAISS baseline: 13.4 ms latency, 100% context recall, 4/4 Q&A. **Pinecone Serverless (us east 1 free tier): 401.2 ms latency, 100% context recall, 4/4 Q&A** — ~30× slower than FAISS due to network, identical retrieval quality. **2 store comparison.md shipped.** 17/17 tests pass. ## What I learned

- **Adapter pattern pays off immediately** — `VectorStore` Protocol + 4 implementations + same eval harness = compare any store with one CLI flag.
- **pgvector is the dark horse** — completely free (Docker + Postgres), no 14 day expiry, no vector count limit. Best long term option for a personal portfolio.
- **Context recall ≠ keyword recall** — retrieved chunks can have all the right info, but the extractive answer string won't always surface exact keywords. Need a real LLM (Week 3) for answer quality metrics.
- **Each store has its quirks** — Pinecone batch limits, Weaviate syntax, pgvector's `<=>` (cosine) vs `< >` (L2) operators.
