## Problem

Week 1's Mini-RAG uses **FAISS** in-memory. Production RAG systems need durable vector stores with proper metadata filtering, hybrid search, and observability. The question: which store is best for a Milind-scale portfolio project (≤100k vectors, single-region Dublin latency)?

## Approach

1. **Same dataset** — the Ireland CSEP guide (`projects/01-mini-rag-reader/data/sample.txt`) so retrieval is directly comparable.
2. **Same embeddings** — `sentence-transformers/all-MiniLM-L6-v2` (384-dim) across all stores.
3. **Four stores** (all free-tier):
   - **FAISS** in-memory — the baseline reference.
   - **Pinecone** Serverless — flat cosine, serverless.
   - **Weaviate Cloud Sandbox** — HNSW + built-in BM25 hybrid.
   - **pgvector** on Docker or Supabase — HNSW index.
4. **RAGAS evaluation** — `faithfulness`, `answer_relevancy`, `context_recall` with a Hugging Face LLM judge.
5. **Comparison report** — side-by-side metrics with latency, recall, and cost.

## Result

- **FAISS baseline** works end-to-end: 4 canonical questions, 7 chunks, ~13ms mean latency, 100% context recall.
- **RAGAS metrics** wired up with `Qwen/Qwen2.5-1.5B-Instruct` as the LLM judge.
- **19/22 unit tests** passing (3 skipped pending API keys).
- **Docker + docker-compose** for containerized deployment with pgvector.
